# tingyu 验收标准

当前功能基线见 [FEATURES.md](FEATURES.md)，风格定义见 [UI.md](UI.md)，红绿重构见 [REFACTORING.md](REFACTORING.md)，发布范围见 [RELEASE.md](RELEASE.md)。以下“当前功能契约”和“视觉验收”是长期门禁；后面的版本补充保留历史来源，冲突以当前已确认基线为准。新增、变更或移除功能必须在同次发布同步更新功能清单、验收条件、回归证据与发布说明；视觉变更还须更新 UI 规范与批准截图。

## 体验目标
用户从音乐库或搜索进入，播放喜欢的 B 站音频，保存歌单及下载供离线收听。完成证据为播放进度前进、队列/歌单保存、下载文件校验及离线播放成功。退出播放页保留播放，重启恢复数据但保持暂停；失败必须显示原因与恢复入口。

## 状态与交互
| 状态 | 触发与反馈 | 可操作与恢复 | 数据、焦点 |
|---|---|---|---|
| 初始/空 | 首次启动、无歌单/下载 | 搜索、新建歌单 | 不自动播放 |
| 处理中 | 搜索、解析、下载 | 进度、取消或暂停 | 切页保留输入与滚动；切页收起键盘 |
| 成功 | 播放、保存、下载完成 | 播放控制、删除、离线重播 | 下载完整后才标为完成 |
| 失败 | 风控、断网、失效链接、写入失败 | 明确原因、重试/换曲 | 不丢失歌单；残缺文件不冒充下载完成 |
| 无可用操作 | 无当前曲目/无上一首等 | 禁用或明确提示 | 禁用状态不只靠颜色 |
| 重启/登录过期 | 进程关闭、凭据失效 | 暂停恢复、重新登录 | 保留库数据，凭据只存系统安全存储 |
| 全屏/系统交互 | 冷启动、键盘、后台恢复、边缘滑动 | 状态栏常显，图标随主题明暗切换 | 内容背景铺满；刘海区域控件保持安全 |

- 固定设备、视口、主题、文字缩放、播放/加载状态、曲目/封面数据及滚动位置，保存变更前后截图和差异说明；不能拿静态提案代替实际运行截图。
- 至少覆盖音乐库、搜索、喜欢、下载两 Tab、歌单、设置、歌曲详情、队列、歌曲菜单、歌词表单与空/失败状态；按改动选取必验页，发布前覆盖受影响的完整矩阵。
- 普通布局矩阵中的组件测试不能代替横屏、刘海、屏幕阅读器和物理设备检查；未执行时单列 NOT RUN。减少动态与正常动画都要覆盖，不能只关闭动画来掩盖问题。
- 纯结构重构应保持视觉；截图有差异时解释并复核。预期的视觉更新须用户确认并更新规范/基准；不允许为通过测试而盲目覆盖截图。
- 保留真实数据与可读性：玻璃强度、动画和封面不能妨碍文字、状态或操作。模拟器截图通过不代表真机滚动流畅或真实人耳播放正常。

## 执行顺序
1. `sh tool/flutterw.sh analyze` 与 `sh tool/flutterw.sh test`。
2. `python3 tool/run_acceptance.py --device emulator-5558 --live`，保存完整日志。
3. 模拟器执行 G03–G06，保存截图、系统窗口信息、日志；连接真实 API 的步骤需单列结果，风控不算通过。
4. 仅构建 arm64-v8a：`sh tool/flutterw.sh build apk --release --target-platform android-arm64 --split-per-abi`，执行 `python3 tool/verify_android_release.py` 校验 G08；执行 `python3 tool/check_android_fullscreen.py --device emulator-5558 --apk build/app/outputs/flutter-apk/app-arm64-v8a-release.apk` 对同一 APK 复测全屏生命周期。
5. 工程侧门禁通过后，附结果报告提交人工验收；G07 与设备厂商差异留到指定真机执行，明确标为待验证，不冒充已通过。

模拟器可以本机先验导航、布局、存储、网络和播放器，但蓝牙、来电、厂商省电与真实锁屏行为必须补充真机测试。

本轮执行结果见 [ACCEPTANCE-2026-10-16.md](ACCEPTANCE-2026-10-16.md)。真实扫码、收藏夹权限与风控不能用响应夹具替代。

自动回归必须使用隔离设备：`TINGYU_EMULATOR_TEST=1 TINGYU_EMULATOR_HEADLESS=1 sh tool/android_emulator.sh`，设备 ID 为 `emulator-5558`。`emulator-5556` 留给人工验收，自动脚本会拒绝在该设备运行，避免测试构建降级卸载或夹具污染账号资料。

## 0.1.3 交互稳定性补充
- 音乐库显示顺序独立于历史播放顺序；CID 占位曲目解析、重复加入及数据库重开后均不得改变音乐库相对顺序。
- 播放模式通过不同图标区分，并提供完整中文长按提示/无障碍名称（按最新确认稿不常驻说明文字）；单曲循环仅影响自然播完，手动上一首/下一首仍切歌。清空队列后停止且不能恢复已清除的曲目。
- 异步按钮在完成前禁止重复触发；搜索失败重试同一页，忽略旧请求并按稳定 ID 去重。
- 歌单/歌词弹窗控制器随实际控件销毁；取消歌词偏移不保存；手动歌词不得被迟到的自动匹配覆盖。
- 下载中暂停/移除应等待传输取消完成；缺失文件不能标为离线可播；删除文件保留歌单和喜欢。
- 音量检查区分系统媒体音量、播放器增益和音源本身。切歌及离线回放保留播放器增益，暂停时音量控件仍正确更新。

最新专项记录见 [0.1.3 交互验收](ACCEPTANCE-2026-10-16-INTERACTIONS.md)。`--live` 运行匿名公共 BV 的真实 Android 解码/下载/离线回放；不替代真实账号、关键词风控与物理设备验收。脚本同时检查开始和结束源码指纹，代码变化则本轮结果失败。

## 0.1.4 精简与图标反馈
界面文案和入口遵循 [UI.md](UI.md)。模式直接点击轮换，不出现选择弹窗；下载按钮无外置文字，状态由进度/图标/勾选表达，长按与无障碍保留完整说明；非音乐库页面无常驻账号入口。歌单次要操作收进更多，必要错误和删除确认不得删除。新专项记录见 [0.1.4 验收](ACCEPTANCE-2026-10-16-MINIMAL.md)。

## 已确认曲库与歌单交互门禁
- 音乐库齿轮打开独立设置页；非设置页面无常驻登录。手机内容菜单从底部展开，必要短文字保留。
- 具体歌单显示封面、歌曲数量、可选简介；返回、播放全部、整单下载、排序、多选可达。
- 排序按具体集合持久化，播放不改变排序；播放全部按展示顺序建立队列。名称/简介编辑兼容旧数据。
- 多选显示数量、全选/取消，底部提供批量加入歌单、下载；具体歌单可确认移除。取消不改数据；移除保留下载、喜欢、库记录与当前播放。
- 系统返回在多选时先退出多选，在歌单时返回音乐库；手动返回行为一致。
- 模拟器边播边下失声单独列项；原生解码/进度通过不能替代人耳可听输出。Magic5/MagicOS 7.1 竖屏亦须物理设备复验。
