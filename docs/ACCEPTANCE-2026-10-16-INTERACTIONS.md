# 0.1.3 交互稳定性验收 · 2026-10-16

本轮是 Android 交互修复的工程验收，供后续人工复核；不等同于三端正式发布验收。模拟器自动测试全部在独立 `tingyu-regression / emulator-5558` 执行；人工验收设备不装夹具、不清数据。

## 修复与回归范围

| 问题 | 修复与验证 |
|---|---|
| 点击播放后音乐库顺序变化 | CID 占位曲目解析后在原位置替换，合并队列/喜欢/歌单引用；保存独立音乐库顺序，数据库重开后不变。最近播放按播放历史更新属于预期 |
| 模式不容易发现 | 详情页底部固定显示“列表循环 / 单曲循环 / 随机播放 · 切换模式”；迷你播放器有模式入口；单曲循环时手动切歌仍前进，自然结束才重复本曲 |
| 清空队列仍能继续旧曲 | 清空/删除当前项时停止播放器并清除当前状态，随后播放不会恢复已清除项目 |
| 异步重复点击与失败反馈 | 公用按钮在请求完成前阻止重复触发；鼠标/触控/键盘共享规则；操作失败显示恢复提示，旧搜索响应不覆盖新查询，分页失败重试同一页且去重 |
| 歌单/歌词弹窗关闭异常 | 输入控制器由弹窗控件生命周期持有，退出动画完成后释放；新建空名校验、改名、删除确认与取消均回归 |
| 歌词取消仍修改偏移、自动结果覆盖手动选择 | 偏移先保存在弹窗草稿，取消不提交；自动请求有代次标识，迟到结果不得覆盖用户手动保存的歌词及离线缓存 |
| 下载状态和文件生命周期 | 支持暂停/重试；移除活动下载先等待网络取消，再清理临时文件；文件丢失后标记失败，可重试；删除下载保留歌单和喜欢；歌曲操作菜单补齐下载入口 |
| 返回与导航 | 固定详情返回和底部播放控件；按钮返回/系统返回保留来源页滚动与播放；20 次 tab 切换保留搜索和滚动并收起键盘 |
| 音量偏小与控件状态 | 人工模拟器系统媒体音量原为 5/15，已调为 10/15；播放器默认增益为 1；原生流播放/离线播放均验证增益不变。暂停时桌面音量滑块现在仍能及时刷新 |
| 登录与导入布局 | 25 个长标题收藏夹可滚动选择，底部导入固定可见；二维码过期/刷新/已扫码/确认/登录过期/退出均有组件级回归。全部使用响应夹具，不代表真实扫码验收 |

## 重复执行

```sh
TINGYU_EMULATOR_TEST=1 TINGYU_EMULATOR_HEADLESS=1 sh tool/android_emulator.sh
python3 tool/run_acceptance.py --device emulator-5558 --live
sh tool/flutterw.sh build apk --release --split-per-abi
python3 tool/check_android_fullscreen.py --device emulator-5558 --apk build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
```

脚本只接受独立 AVD，并核对开始/结束源码指纹；代码中途变化则失败。人工设备仅允许同签名 Release 覆盖安装，不卸载、不降级、不清数据。

## 人工复核路径

1. 音乐库记录几首歌的原有位置，分别播放，返回确认顺序稳定；“最近播放”会按历史更新。
2. 展开播放页，在底部中文模式入口依次选列表循环、单曲循环、随机播放；验证手动上下首，滚动后按钮返回和系统返回仍能退出且继续播放。
3. 新建、改名歌单；加歌、移出歌曲；删除先取消再确认，喜欢与音乐库仍在。
4. 调整队列、删除当前项、清空取消/确认；清空后不继续旧曲。
5. 下载一首歌，从下载页播放；断网后验证本地播放。删除下载，确认歌单/喜欢仍在。
6. 保存歌词，再调整偏移后取消；确认取消不改变保存结果。切换主题，检查文字、按钮与选中态。
7. 使用自己的账号复核扫码及收藏夹导入。此步骤需要本人，自动响应夹具不能代替。
8. 关闭并重开应用，确认数据和主题保留、播放保持暂停；手机实机再验锁屏/来电/蓝牙。
