# 全局操作反馈与面板退出方案（已确认，实施中）

## 范围与已确认项

用户已确认此方案，并于后续明确要求开始开发；按下列规则逐项实施与验收。

- 清脆刻度音第六版暂时采纳；仅自定义时长滚轮跨刻度触发。
- 首页布局保持原样；定时 A、登录图 5 继续保留。
- 本方案覆盖歌曲更多、队列操作、歌单选择、下载、设置、外部跳转与破坏性操作，统一状态与退出规则，各操作独立决定是否关闭。

## 体验目标

用户点击后能看清“操作是否收到、结果是什么、如何恢复”，并可继续当前任务。退出应来自用户主动收起、明确完成流程或离开当前应用，不使用固定等待若干毫秒后强制关面板来掩盖问题。

已检查源码：
- `lib/ui/app.dart` 的 `showTrackActions`：喜欢、下一首播放、加入队列成功后直接 pop；喜欢行未像下载行一样订阅状态。
- `showQueueTrackActions`：队列上移、下移等操作先 pop，再执行。
- `showAddPlaylist`：单选歌单成功后直接 pop，缺少完成结果。
- `showDownloadActions`：补全歌词、导出、删除操作先关闭菜单。
- `lib/ui/settings_views.dart`：音质选项变更后直接关闭。
- `lib/ui/playback_settings_views.dart`：定时持有草稿，用户收起后生效；此已确认契约保留。
- `lib/controllers/library_controller.dart`：toggleLike 更新内存并通知后再 save，不能把内存更新当作保存成功。

上述是源码检查，未声称完成原生交互复现或全应用验收。

## 状态与退出矩阵

| 操作 | 收到操作与处理中 | 成功反馈 | 面板退出 | 失败与恢复 |
| --- | --- | --- | --- | --- |
| 喜欢／取消喜欢 | 当前行立即有按压反馈；提交期间仅锁定该行 | 原位实心／空心心形切换，文字变为相反动作；其他行不移动 | 保持；用户主动收起 | 行内显示失败与重试，恢复原状态；保留歌曲上下文 |
| 下一首播放 | 当前行防重复提交 | 显示“已设为下一首”，提供查看队列；不改为立即播放 | 保持 | 原位失败，可重试 |
| 加入播放队列 | 当前行忙碌，保持菜单可操作 | “已加入队列”，可查看队列；根据现有去重契约处理重复，不额外插入 | 保持 | 原位失败，可重试 |
| 队列上移／下移 | 只锁定相关排序操作 | 队列移动，标题位置序号随结果更新；到边界时禁用对应动作 | 保持，支持连续移动 | 恢复原顺序与序号，原位重试 |
| 移至下一首 | 操作项防重复 | 更新队列序号和“已移至下一首”状态 | 保持 | 恢复顺序，不误报成功 |
| 从队列移除 | 按曲目 ID 操作，保留撤销所需位置与优先级 | 成功后结束该歌曲的操作面板，在队列上显示“已移除 · 撤销” | 成功后回到队列；对象已不在队列中 | 失败留原面板；撤销恢复原位置／播放顺序，不重启正在播放的歌曲 |
| 下载／暂停／继续／重试 | 原行变为任务当前状态；入队与传输分别反馈 | 进度、暂停、失败或已下载互斥显示 | 保持；完成后也不突退 | 保留失败状态与重试；不能把加入任务等同下载完成 |
| 补全歌词 | 原行显示处理中，避免重复任务 | 显示已补全；仍无歌词则显示真实结果 | 保持 | 留原处，显示原因并重试 |
| 加入歌单 | 同容器进入歌单选择子层，保留来源与滚动位置 | 目标行显示“已添加”勾选，可继续添加其他歌单；已有曲目显示“已在歌单中” | 点完成回到原歌曲菜单；返回只退一层 | 保留选中目标与错误，不关闭选择层 |
| 新建歌单 | 在选择流程内进入输入子层；提交期间保留输入 | 新歌单出现在选择层，显示是否已添加当前歌曲 | 成功返回歌单选择层；取消回上一层 | 输入保留，原位修正；不因新建失败丢失原菜单 |
| 多选批量加入／下载 | 按本次选择集合执行，显示处理数；防止重复提交 | 汇总成功、失败、已存在数量 | 全部成功后明确完成；部分失败保留失败项选择 | 不把部分成功显示成全部成功；可只重试失败项 |
| 音质／主题／排序／播放模式 | 选中态或预览即时更新；不反复触发已选值 | 勾选与当前值体现结果 | 选择面板保留供比较；直接轮换模式保留既有短时名称提示 | 恢复实际已保存值；说明失败 |
| 倍速／音量／歌词字号与偏移 | 连续调节实时反馈；恢复作用域明确 | 数值与效果一致 | 不因单次调节关闭；沿用原有保存／取消契约 | 失败显示实际结果，不把失败设置当已生效 |
| 定时关闭 | 保留草稿，预设／滚轮／播完暂停只改草稿 | 用户主动收起后应用；播放页定时状态体现结果 | 仅用户收起；切后台／销毁不提交，未改动不重置 | 失败保留既有有效定时，不暗中关闭 |
| 在 B 站打开／登录 | 发起期间该行忙碌；菜单不先消失 | 系统接管后等待实际返回或确认；登录成功须有会话验证 | 不以调用成功强关来源；回到应用保留上下文 | 无 App、取消、超时等留在来源可重试；外部打开不等于登录成功 |
| 导出歌曲 | 准备阶段显示进度；准备好才调系统分享／保存选择 | 仅在平台能确认时显示已导出，否则只显示真实可证实状态 | 系统选择器取消后回来源菜单 | 不以打开选择器当作导出完成；失败可重试 |
| 移出歌单 | 同一容器进入简洁确认层，说明下载保留；取消恢复原菜单 | 成功回列表，显示“已移出 · 撤销” | 仅成功后退出该对象操作层 | 失败保留确认层；撤销还原成员及原排序，不改下载 |
| 删除下载／清理文件／删除歌单／退出账号 | 显示实际影响范围，明确确认；取消返回来源 | 真实完成后反馈，不先报成功 | 确认后处理中不丢失承载页面；成功回适当列表／设置 | 不可恢复文件必须确认；失败保留可恢复状态，部分删除按实际报告 |

## 截图中的“取消喜欢”具体设计

1. 点击后菜单留在原位置，标题、歌曲与其他操作不移动。
2. 当前行完成后由粉色实心心形＋“取消喜欢”，变为中性空心心形＋“喜欢”，约 150–180ms 淡变；减少动态时直接切换。
3. 面板内固定反馈位显示“已取消喜欢”，不盖住操作行、不因文字出现顶动布局；该反馈可短时淡出，面板始终保留。
4. 用户可以直接再点“喜欢”恢复，不额外弹二次确认。
5. 从心动收藏入口操作时，背景列表按真实状态更新；操作面板绑定曲目 ID／快照，不依赖该列表行继续存在。取消最后一首也不能让面板意外销毁。
6. 用户主动收起后，列表保留原滚动锚点，给出“已取消喜欢 · 撤销”；撤销窗口建议 5 秒，并按无障碍阅读需求延长。需要恢复到取消前的收藏顺序，不简单追加末尾。
7. 撤销必须设置明确目标状态，并检验该次操作是否仍有效；如果用户已重新喜欢，旧撤销不能再次反转结果。保存失败回滚、展示原因；正在播放不受喜欢状态改变影响。

## 全局反馈规范

- 瞬时操作即时按压反馈；约 300ms 仍未完成再出现行内加载标记，防止短任务闪烁。
- 一次性命令与状态切换分开：命令可显示结果行，状态切换以新状态为主。不能把“喜欢”成功提示替代心形状态。
- 完成反馈与按钮位置稳定；面板内结果不使用被面板遮挡的页面 Snackbar。回列表后才使用列表承载的反馈条。
- 普通错误留原处、保留输入和上下文；不再一律叠“操作未完成”对话框。需要决策、权限或破坏性影响时才用确认层。
- 同一个操作容器维护返回层级，避免关闭菜单又从底下弹出新面板；新建、歌单选择、删除确认的取消均回到来源。
- 同步中的操作不能被重复提交。关闭 UI 不代表取消已接受的后台任务；重开后呈现真实任务状态。
- 以曲目 ID／任务 ID 锁定异步目标，不使用会随排序变化的列表索引。错误、撤销与完成回调不能更新已失效页面或跳回错误路由。
- 全局回退：子层返回上一层；根面板主动收起；页面返回遵循原导航。Android 返回、遮罩点击、下拉收起、桌面 Escape 分别验证。

## 实施边界建议

沿用 Flutter、LibraryController、主题组件与原有导航，不更换架构。业务层负责实际结果、持久化失败恢复和明确状态命令；操作面板负责忙碌态、结果反馈和退出策略。仅在确有多处相同行为时复用行反馈组件与操作容器，不能全局删除 pop 或机械加延迟。

分两批实施：
1. 高频歌曲／队列／下载操作，加失败和撤销基础；修复喜欢行订阅及最后一首取消的生命周期。
2. 歌单子流程、批量部分失败、设置、导出、外部跳转、破坏性操作，按矩阵逐项验收。

本方案不修改先前已确认的定时草稿契约，不扩大到首页视觉重设计。

## 验收门禁（实施前定义，执行结果见版本记录）

- 点击取消喜欢后菜单保留；文案、图标、底层列表与保存结果一致；可立即重新喜欢。
- 最后一首取消、快速连点、保存失败、撤销后重复点击、关闭后回调等场景不误关、不反转新状态、不串歌曲。
- 队列连续上移／下移保持菜单，位置实时更新；移除撤销恢复原播放顺序与优先级。
- 下载加入队列、下载完成、失败、暂停互斥展示且不突退；重复操作不创建重复任务。
- 歌单选择与新建、删除确认的取消能回到正确来源，保留输入和滚动位置；批量失败只重试失败项。
- 定时仅用户收起才提交；未改动、切后台和销毁不重置／提交；刻度音仅自定义滚轮触发。
- B 站打开失败／取消不丢上下文，确认会话前不显示登录成功。
- 普通操作不弹多余确认，不固定延时自动关菜单；破坏性操作有明确影响范围。
- 小屏、大字号、减少动态、读屏、Android 返回、桌面键鼠与 Escape 分别验证；反馈无遮挡、不靠颜色唯一表达。
