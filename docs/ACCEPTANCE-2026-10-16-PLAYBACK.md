# 0.1.6 播放逻辑专项验收

## 根因与修复

音乐库/喜欢/具体歌单的歌曲行原来只调用单曲播放，将点过的曲目逐个追加到旧队列。可见列表有 51 首，并不代表播放队列有 51 首；当旧队列只有两首时，随机自然只会在两首之间切换。原随机算法每次重新抽取，上一首也重新抽取，没有首轮覆盖和真实播放历史。

本轮按显示列表建立队列，列表排序不受播放影响。随机播放使用可持久化的候选顺序与独立历史，不打乱用户可见队列；每轮全部成员各一次，新一轮第一首不紧接着重复上轮最后一首。上一首返回真实历史，下一首先沿历史向前；明确的“下一首播放”优先于历史/随机候选。

## 操作契约

| 操作/状态 | 规则 |
|---|---|
| 音乐库/喜欢/歌单点歌 | 用当前显示集合及其排序建立队列，从点击歌曲开始 |
| 最近播放卡片 | 作为音乐库快捷入口，建立当前音乐库队列 |
| 搜索点歌 | 保留现有队列，加入并播放指定搜索曲目 |
| 已下载列表点歌 | 建立全部已完成下载的队列，文件存在性仍由播放服务检查 |
| 顺序/列表循环 | 按可见队列切换，首尾循环 |
| 单曲循环 | 自然播完重播，手动上下首仍切歌 |
| 随机下一首 | 一轮内不重复；用户主动回退、点歌或指定下一首可以重播 |
| 随机上一首 | 返回实际播放历史，不重新随机；历史最多保留 2048 次 |
| 下一首播放 | 在三种模式的手动切歌中优先执行；单曲自然循环保持本曲 |
| 重复加入队列 | 已有成员不重复、不移位；指定下一首才调整优先级 |
| 模式切换/新集合 | 新集合重建随机周期；模式切换重建周期，保留指定下一首 |
| 队列增删/顺序调整 | 不复活已移除曲目；新加入成员进入当前周期；移除正在播放曲目按既有规则停止 |
| 重启/恢复 | 保持暂停，恢复未完成随机周期和播放历史；开始播放不会重置周期 |
| 快速切歌/自然完成同时到达 | 同一时间只执行一次上下首；界面、通知栏和自然完成共用规则 |
| 新选曲覆盖慢请求/清空 | 串行提交原生音源操作；旧请求不能覆盖新歌曲，清空后不能复活；清空期间的新集合不被旧清空结果抹掉 |
| 失效曲目 | 显示失败原因，不把未成功打开的曲目记为实际播放历史，可继续切到其他歌曲 |

## 验证范围

- 精确 51 首用例：旧两首队列 → 列表点歌 → 51 首完整队列 → 随机不重复 → 重启暂停 → 继续完成本轮。
- 有限边界 0/1/2/51/200 首，51 首多轮覆盖、前后历史、优先下一首、增删及 CID 别名。
- 延迟注入：快速下一首/完成合并、慢音源打开后选新歌曲、加载中清空、清空中开始新集合、加载期间模式切换、失效曲目历史。
- 组件回归验证真实歌曲行的列表范围和喜欢集合隔离。
- 独立 Android 回归通过界面实际连续切换 51 首（本地 WAV 原生解码），查看队列数量并执行上一首/下一首往返；同时保留账号导入、主题、队列、下载及离线流程。
- 真实公共 BV 解码、下载、并发播放状态与离线播放单列；不作为人耳听感或真实账号验收证据。

同步落实三主题界面层次：页面底色、歌曲内容面、独立悬浮播放器、弱化导航；A 为暖石墨灰播放器，B 为雾蓝，C 为克制粉色。已下载保留图标及语义选中态、去掉色块。共用主题覆盖搜索、歌单、下载、设置及播放页。视觉结果以原生截图复核。用户实机报告的播放、下载、顶部显示通过保留；不将模拟器声音问题自动记为关闭。

最终 PASS/FAIL 以机器报告、对应 Release SHA 与工具清单为准。本轮仅使用隔离回归设备，不向人工设备注入测试资料。
