# tingyu Mac UI 与本地状态审查（2026-10-25）

## 结论与范围

审查基线：HEAD `4792eaf`，应用版本 0.1.27。未修改产品实现，未提交、发布或操作真实账号退出。新增独立复现脚本和本报告；既有未跟踪设计素材保留。

发现 6 项由隔离测试复现的问题，以及 3 项代码确认的交互问题。最优先的是启动恢复可能覆盖本地状态，其次是 Mac 没有呈现播放错误。一级导航总体已经扁平，问题集中在歌单选歌、歌词操作和待播菜单等子流程，不建议重新增加主页或全面改版。

本轮检查音乐库/最近播放、歌单添加、搜索、播放栏、详情、歌词入口、队列、定时、音量、账号、外观/播放/存储设置，以及数据保存恢复。以项目最新 Mac UI 规范为准；Android 历史规范不直接套用于 Mac。

## 已复现问题

### A01 · P1 · 初始化期间自动保存会覆盖历史、歌单等本地状态

- 位置：`lib/controllers/library_controller.dart:68`、`:275`、`:379`；`lib/services/storage.dart` 的凭据读取超时为 5 秒。
- 控制器构造后即启动每 5 秒自动保存；`initialize()` 先等待账号凭据，再加载歌曲与 `library` 状态。凭据读取慢或随后本地读取耗时跨过首个保存周期时，空的内存状态先覆盖数据库，再被初始化读回。
- 隔离测试预存历史与歌单，把账号初始化延迟 5.2 秒，自动保存后数据库中的 history 已变成 `[]`。这是持久化数据丢失，不是单纯视图隐藏；喜欢、队列、设置和当前歌曲等同一状态中的字段也受影响。歌曲独立表仍存在。
- 直接调用退出账号、关闭再重开隔离数据库的对照测试通过：历史保留。退出代码本身仅清凭据与 profile，没有清历史。
- 真实本机数据库只读统计：歌曲 51 条，history/queue/likes/playlists 均为 0，无 current。该形态与上述缺陷一致，但没有那次操作的日志，不能证明用户所述事件的唯一根因，也不能保证已丢失的顺序和歌单关系可恢复。
- 修复方向：恢复成功之前禁止任何状态写入；成功后启动自动保存，初始化失败不覆盖旧库。增加慢钥匙串、超时、慢数据库、退出账号后重启的回归检查。

### A02 · P1 · 播放失败、部分桌面与凭据错误在 Mac 没有可见反馈

- 位置：`lib/ui/mac_workspace.dart:259`；`lib/controllers/library_controller.dart:620`。
- `play()` 捕获异常写入 `p.error`，不向上抛出。Mac 页面只显示 `searchError` 和歌词错误，没有渲染 `p.error`；外层 `report()` 也无法捕获已被控制器处理的异常。
- 离线夹具播放：控制器错误为“测试网络断开，请重试”，界面找不到该文字。用户只看到解析结束却无法播放，容易反复点击。
- 同一缺口影响通过 `showError()` 报告的托盘、退出保存等故障。应提供稳定错误区域和针对失败动作的重试，避免把所有问题变成额外阻塞弹窗。

### A03 · P2 · 无效定时输入静默提交此前有效值

- 位置：`lib/ui/mac_workspace.dart:1274`。
- 输入 15，再改成 999，收起面板：界面没有校验提示，实际启动 15 分钟定时。删除文本或输入非数字也不清除旧草稿。
- 隔离组件测试已复现。应显示有效范围并阻止提交无效草稿，保留用户输入以便修正。

### A04 · P2 · 添加歌曲离开 Mac 工作区，桌面播放栏消失

- 位置：`lib/ui/mac_workspace.dart:939`、`lib/main.dart:129`、`lib/ui/playlist_add_views.dart:42`。
- 路径：侧栏歌单 → 添加歌曲 → 在线搜索。第一步推入独立共享 Scaffold，第二步进入 AppShell，桌面侧栏和固定播放栏不连续。
- 组件测试打开添加歌曲后已找不到 `mac-playback-bar`。这属于桌面任务上下文丢失，不是正常的一级导航层次。
- 建议在工作区内承接选歌，或使用有明确返回来源的桌面任务面板；本地与在线选歌可放同一任务的两个来源，避免连续整页切换。

### A05 · P2 · 最近播放的 Cmd+F 无效

- 位置：`lib/ui/mac_workspace.dart:277`。
- recent 没有本地搜索框，但快捷键将焦点交给未挂载的 localFocus。测试按 Cmd+F 后页面仍无可用输入框。
- 应对 recent 跳转全局搜索或提供明确的当前集合搜索；保留其他页面一致的快捷键语义。

### A06 · P2 · “待播清单”没有反映实际循环/随机播放顺序

- 位置：`lib/ui/mac_workspace.dart:1043`；对照 `lib/controllers/library_controller.dart:734`、`:756`。
- UI 仅取 `queue` 中当前索引之后的部分，不使用播放控制器的优先队列与随机顺序。
- 两首歌曲、列表循环、当前为最后一首时，界面显示“本轮没有待播歌曲”，实际下一首会回到第一首。组件测试复现这个矛盾；随机模式的顺序差异由代码确认，未单独做随机实机验证。
- 应从同一播放计划生成预览，或把界面明确定位为完整队列；不能继续以截取数组冒充实际“接下来”。

## 视觉、层级与按钮审查

以下属于有依据的改进建议，不与已复现故障混算：

1. **歌词入口多绕一层。** 详情空态“匹配或导入歌词”和右上省略号都调用 `showLyrics()`，先看到“显示与排版/匹配/编辑/偏移”再进入目标（`mac_workspace.dart:1490`、`app.dart:4381`）。明确动作应直达匹配/导入；省略号保留完整选项。当前两个入口既重复，又没有实现文案承诺的直达。
2. **队列的轻操作使用居中模态框。** 队列浮层上再开“上移/下移/移除”大弹窗，背景整体变暗；截图可见标题到动作之间留白偏大，两层关闭入口同时在视野内。优先采用锚定菜单或行内操作，破坏性确认再单独出现。现状不是死按钮，但层级与视觉权重偏重。
3. **恢复按钮在默认状态仍可点。** 音量 100%、倍速 1×仍显示可操作恢复；设置和播放选项又各有一套倍速调节。多入口可以有快捷与设置两种使用场景，但默认值时恢复动作应禁用或弱化，避免无变化点击。不要把所有重复入口一律删除。
4. **800×600、大字设置首屏可操作区不足。** 播放设置中标题、分组、间距和固定页脚占据大量高度，倍速按钮只露出上缘，滑杆需继续滚动。没有 RenderFlex 溢出，但“测试通过”不等于首屏易操作。建议压缩组间留白或优化可滚区/页脚占比，保留目标尺寸。详情长标题同样依赖封面列滚动，元信息与更多操作不在首屏；可改善可发现性。

已检查且未发现新的明显几何问题：普通字号 800×600、1024×768、1280×800 的固定播放栏、音量浮层、常规详情、账号导入，以及 1024 窗口的存储数字居中。哔哩粉/夜间暗大字场景经过既有组件矩阵；另外两个主题没有单独进行本轮原生视觉验收。封面夹具使用占位图，不能据此评价真实封面裁切质量。

没有证据支持把侧栏各资料库项、全部歌单、新建歌单、下载两分区等判为“无意义按钮”。它们具有独立目的；没有必要仅为减少按钮数量删去功能。零临时文件时清理按钮已有禁用逻辑，也不列为缺陷。
