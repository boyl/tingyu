# 0.1.7 队列、本地搜索与主题稳定性

## 问题与改动

- 队列原来没有当前行状态、滚动控制器或定位逻辑。现在以曲目 ID 标记当前行，图标与语义同步区分播放/暂停；首次布局即使用当前行偏移，布局完成后居中。打开队列、切换当前歌曲会定位，手动浏览后可点击定位；上移/下移当前歌曲后仍可见。清空、移除、优先下一首与随机历史契约保留。
- 音乐库、喜欢、具体歌单、下载页增加搜索图标，展开当前列表筛选。匹配歌名、UP 主、BV 号，忽略大小写并支持多个空格分隔关键词；没有网络请求。筛选范围内点歌/播放全部/多选都使用当前匹配集合，清除只恢复展示，不删库。空结果可清除恢复；收藏夹和最近播放在输入筛选时暂时收起。
- 主题颜色过渡和 Offstage 的暂停动画会给隐藏页面留下旧的过渡状态；同步分类切换也曾进入异步 pending 淡化。取消全局主题渐变与 Pressable 隐式颜色动画，同步回调不再进入 pending，按压缩放、焦点、悬停及真实异步防重复仍保留。A/B/C 不分叉组件。
- 原歌词仅用 LRCLIB 清洗后的完整标题搜索并直接使用第一条，方括号内容被整体删除。现在保留括号内文本、优先提取书名号/引号歌名，最多三组关键词；按歌名、时长差异和同步歌词排序，明显版本差异及长合集不自动选。自动请求过期即停止，不能覆盖手动歌词；本地缓存、手动匹配/粘贴/时间偏移保留。

- 歌单操作入口由“编辑名称与简介”缩短为四字“编辑歌单”；简介由固定两行改成单行起步、最多四行，使用紧凑内边距，使短简介紧贴输入下划线。保存、取消、空名称验证与已有数据保留。

## 外部实现参考与边界

参考机制来自 [HanversionOvO/BiliMusic 的歌词服务](https://github.com/HanversionOvO/BiliMusic/blob/master/src/services/lyrics.ts)：标题清洗、多关键词、候选评分、缓存和手动纠正；该项目使用 OIAPI QQ Music Lyric。本项目独立实现现有 LRCLIB 的匹配改进，没有复制其代码或接入公共代理。

本机公开 API 连通性探测：晴天返回 20 个含歌词结果；A Cruel Angel’s Thesis 返回 20 个结果，其中 18 个有歌词。仅统计元数据，不保存/输出歌词正文。这不能替代用户手机网络、全部中文/翻唱/合集覆盖率验证，也不保证每首都有同步歌词。多源接入仍需独立验证接口可用性，未宣称已经完成。
