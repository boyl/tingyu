## 已观察问题与修复依据

Mac 部分推荐歌曲首次网络播放失败，再次点击播放成功。本轮复现发现：DASH 解析丢失音频 MIME，缓存代理将 CDN 的 `application/octet-stream` 直接作为返回类型，Mac 原生播放器报 `-11828`；再次播放命中完整 `.m4a` 缓存后成功。修复应保留源媒体类型并只纠正 CDN 缺失/通用类型，不通过额外重试掩盖首次失败。上述为问题证据，不能代替修复后的验收结果。

### 专项证据边界

- 上表日志位于 `artifacts/release-035/`。缺失响应头夹具已移除 Dart 默认 `text/plain`，实际不发送 Content-Type，避免测试假设与真实响应不符。
- 最终固定已复现的 `BV1KGxv6GEo4`、`BV1Bu411f7jk`，以 CID 0 推荐摘要进入真实详情、解析与 CDN 全链路；首播使用全新缓存目录，再验证缓存重播，没有响应头覆盖。推荐列表展示与排序不是本用例断言。
- 按上述样本顺序，Mac 首播进度 2003/2002 ms、缓存重播 2001/2002 ms，四次 CDN 响应均为 `application/octet-stream`；Android 首播 1721/1693 ms、缓存重播 1813/1811 ms，两次 CDN 响应均为同一通用类型。进度证据不等同于物理听感。
- 中间测试问题均发生在播放前：Android 初版在已有加载结束前取样，Mac 动态精选没有符合测试时长筛选的样本。最终使用固定真实复现样本消除选样不稳定；没有新增生产重试，不将这些夹具问题记为播放器回归。
- 36 项专项覆盖缓存复用、下载转存、取消和截断等已有测试；未据此宣称已有下载文件的独立原生回放或额外失败重试特例已验收。

### 复现命令与门禁说明

从项目根目录执行。原生入口 `artifacts/release-035/native.dart` 仅调用 `integration_test/playback_cache_test.dart` 与 `integration_test/recommendation_playback_test.dart` 的 `main`：

```sh
sh tool/flutterw.sh test --no-pub test/bilibili_audio_mime_test.dart test/core_test.dart test/playback_cache_test.dart
TINGYU_ACCEPTANCE_DEVICE=emulator-5558 sh tool/flutterw.sh drive --no-pub --driver=test_driver/integration_driver.dart --target=artifacts/release-035/native.dart --dart-define=RUN_LIVE_PROBE=true -d emulator-5558
python3 artifacts/release-035/run_gate.py
```

Mac 先以同一入口和 `RUN_LIVE_PROBE=true` 执行 Debug `--config-only`，再执行下方 `xcodebuild`；框架与应用完成本地 ad-hoc 签名后，用预构建应用运行：

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer sh tool/flutterw.sh build macos --debug --no-pub --config-only --target=artifacts/release-035/native.dart --dart-define=RUN_LIVE_PROBE=true
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -workspace macos/Runner.xcworkspace -scheme Runner -configuration Debug -derivedDataPath build/macos CODE_SIGNING_ALLOWED=NO build
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer sh tool/flutterw.sh drive --no-pub --driver=test_driver/integration_driver.dart --target=artifacts/release-035/native.dart --dart-define=RUN_LIVE_PROBE=true --use-application-binary=build/macos/Build/Products/Debug/tingyu.app -d macos
```

- 初次门禁仅因 ignored 诊断脚本 `baseline.dart` / `probe.dart` 的 unused_import、print 检查失败；保留脚本内容改存 `.dart.txt` 后重跑，没有放宽 `analysis_options`。失败证据：`analyze-initial.log`、`report-initial.json`。
- `run_gate.py` 包装实际命令 `python3 tool/run_acceptance.py --device emulator-5558 --live`，仅暂移未跟踪设计稿，避免图标扫描将外部设计输入纳入工程清单；`finally` 原位恢复并逐文件比对 SHA-256，证据写入 `local-design-preservation.json`。用户文件保留，这些本地 artifact 不提交。
