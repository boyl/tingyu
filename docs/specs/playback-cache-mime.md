# 推荐首次播放音频类型修复

## 问题与范围

用户确认 Mac 搜索推荐首次点击失败，再次点击成功，并授权先拉取最新代码、修复、跨平台测试、发布及本机覆盖安装（无需备份）。已快进到 `d432a0f`，保留 Windows 0.1.34 更新。

冷缓存真实探测确认：API 成功，CDN 返回 `application/octet-stream`，缓存代理照传，Mac AVFoundation 报 `-11828`；下载完成后第二次使用本地文件成功。同一曲目仅改代理类型为 `audio/mp4` 即首次成功。Android 相同样本首次成功。原始证据在忽略目录 `artifacts/mac-first-play/`。

本次只修复共享音频元数据链路，不添加旧版本兼容层、平台特判、重试或编码选择策略，不迁移缓存/数据库，不变更界面。Windows 使用相同源码，但本机无 Windows 原生运行环境；不能将共享测试视为 Windows 实机验收。

## 契约与验收标准

1. `AudioStream.mimeType` 携带当前选中 DASH 音频流的 `mimeType`；高/标准音质各自跟随选中项。缺失、非字符串或空白字段表示未知。
2. CDN 有具体 Content-Type 时保留它；缺失或 `application/octet-stream`（忽略大小写和参数）时使用解析结果中的真实类型。两者都未知时使用 `application/octet-stream`，不猜测 MP4。
3. 完整流、缓存读取和尾部 Range 返回一致类型；真实 WebM 元数据不得被硬改为 MP4。
4. 原有缓存、离线播放、下载转存、取消与清理行为不变。真实冷缓存推荐播放首次无错误且播放进度前进；不能用第二次成功代替首次验收。
5. Mac、Android 原生夹具使用真实 M4A 字节与泛型 CDN 类型；Windows 保留可运行测试并明确未执行边界。最终源码执行仓库工程门禁。
6. 发布 0.1.35+36 的 Mac DMG 与 Android arm64 APK，Windows 下载沿用已发布 0.1.34，不称其包含本修复。本机 Mac 覆盖安装并验证版本/签名/内容，不备份、不动用户资料。
