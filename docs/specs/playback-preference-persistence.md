# 播放偏好持久化修复

状态：工程验证完成；Android 真机验收待执行。

## 目标

修复应用重启后丢失播放音量、“播完暂停”偏好的问题，并检查同类设置。

## 已确认的原因

- `lib/ui/volume_views.dart` 直接调用播放器 `setVolume`；控制器保存及初始化均没有音量字段。周期保存也无法补救。
- `LibraryController.setSleepTimer` 没有保存结束方式；`SleepTimer.finishTrack` 仅在内存中。
- 定时关闭时提交草稿，`setSleepTimer(null, finishTrack: ...)` 只执行 cancel，忽略新的结束方式。因此只切换结束方式、不启用时长时，重新打开面板也会丢失选择。
- 倍速、播放模式、音质、主题、透明度、歌词显示/字号/居中、列表排序均有保存和读取路径；这是静态检查结论，不代表 Android 重启实测通过。

## 要求与兼容性

- 音量修改即时生效并保存，重建播放器和控制器后恢复，包括静音及恢复 100%。只控制应用增益。
- “播完暂停”作为独立偏好保存，定时未启用、取消、到期及重启后均保留；关闭状态下修改也有效。
- 保留面板收起提交草稿的规则，不提前应用未提交的选择。
- 保留现有契约：进程重启不恢复倒计时、不自动播放、不恢复等待本曲结束状态。
- 旧数据库无新字段时，音量默认 100%，播完暂停默认关闭；无需数据库版本迁移。
- 本轮不新增“记住上次定时时长”行为。定时结束后显示关闭符合当前设计。
- 不调整界面布局，不提交、发布或覆盖用户已有 macOS 工作。

## 方案与影响文件

控制器统一处理音量更新、偏好保存及初始化恢复；音量入口改为调用控制器；定时提交同时保存结束方式，保持取消计时与偏好独立。扩展播放偏好和面板回归测试，并同步相关功能/验收条目。
