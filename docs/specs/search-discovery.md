# 搜索推荐页
Status: Implemented（工程及 Android 原生验证通过；Mac 原生布局确认，真机/人工完整验收待完成）

## 目标与范围
用户已授权实施：保留搜索框和「前往哔哩哔哩」，用「为你发现 + 换一批 + 探索标签」替换固定主题卡片。Android/Windows 与 macOS 共用推荐组件。沿用现有 Controller、BilibiliClient、TingyuTokens/Pressable，不引入依赖、数据库迁移或 AI 服务。

## 体验与状态
核心任务：不知道听什么时发现内容，点击真实曲目播放；输入关键词恢复原有搜索，清空/返回恢复推荐。标签：全部、轻音乐、翻唱、现场、纯音乐。
| 状态 | 反馈和恢复 | 数据 |
|---|---|---|
| 初始 | 进入时加载，不自动播放 | 推荐独立于搜索结果 |
| 加载 | 首次为静态卡片占位，按钮内进度；当前标签换批禁用，其他标签可切 | 保留旧批次 |
| 成功 | 最多 6 首横滑精选 + 10 首连续列表、真实封面/标题/UP 主；喜欢和播放 | 本次会话按标签缓存 |
| 空/耗尽 | 明确无更多内容，可换标签或搜索 | 不循环伪装新批次 |
| 失败/离线 | 显示原因和重试；保留旧批次 | 失败页不推进 |
| 返回/重进 | 保留标签和当前批次 | 重启后重新生成，无持久化 |

## 推荐规则与边界
- 喜欢优先、最近播放其次，最多两条去重线索；优先提取标题片段，补充通用音乐搜索。无历史时通用音乐方向。
- 标签限定候选方向；过滤标题含教程/教学/教你/唱歌技巧等明显教学内容；通过现有在线搜索协议获取候选，不宣称严格音乐分类或 B 站个性化推荐。
- 每次换批最多两次串行搜索；缓冲足够时不请求。每个查询独立分页，失败保留页码供重试。
- 按 BV 去重，同标签本会话已展示不重复，近期听过降权，每批同 UP 主最多两首；不足六首允许较短批次。
- 标签请求隔离；重复加载抑制；销毁后不通知、不写入 UI。不修改现有手动搜索状态。
- 使用实际播放/喜欢入口；仅浏览不自动保存曲目或改变队列。

### 目标、兼容性与范围
- 按可靠供给 → 兴趣覆盖 → 反馈排序顺序推进；手机标签调整纳入第一阶段。
- 沿用 Flutter、现有 Controller/服务边界及 B 站搜索，不增加模型、依赖或外部推荐服务；不更改手动搜索、播放队列、喜欢及历史语义。

### 第一阶段：稳定供给与手机标签
- 修复候选停滞：按应用去重和多样性规则后的可选数量判断是否补充请求，不能用 pending 原始长度挡住分页。因批次限额暂缓的候选与已屏蔽候选分开处理。
- pending 每标签最多 200 条，保留高优先候选；单次请求预算耗尽时允许短批次。连续页无可用结果显示“暂未找到更多”，允许用户继续查找；只有所有源结束且无可选/暂缓候选才宣告耗尽，不自动无限翻页。
- 保留标题教学过滤，审查既有“歌曲推荐”整类排除的误伤；新增明确讲解/教学组合规则。已知时长不足 45 秒只降权，长合集不排除，未知时长不惩罚。不声称严格音乐分类。
- BV 严格去重；仅对规范化后完全相同且有辨识度的标题做跨 BV 近重复降权。保留现场、翻唱、演奏版本信息，不用模糊匹配硬删同曲不同版本，不把 UP 主当歌手。
- 同 UP 主单批最多两条；最近 30 条已曝光内容中该 UP 主出现至少两次时额外降权，稀缺时不硬性阻断供给。
- 持久保存最近 7 天、最多 1000 条真实曝光 BV；同标签本会话不重复，跨标签/跨启动的近期曝光降权。曝光定义为卡片/行进入可视区至少一半持续 1 秒，不能将下载或缓冲候选算成看过；仅保存 BV、时间及必要作者标识。
- 手机标签将 Wrap 改为单行横向滚动，沿用 Pressable、选中样式与至少 48dp 点击目标。选中项保持可见，换标签不重置标签条位置；横向手势不触发纵向加载。桌面保留一行，空间不足同样可横滚。

### 第二阶段：扩大兴趣覆盖
- 候选种子池来自最近 50 条喜欢和最近 50 条播放，先按 BV 合并；尚无有效收听统计时，播放记录仅作弱线索。
- 每轮最多选择 6 个不同的标题线索，喜欢优先兼顾近期和轮换；每种来源有候选时都保留覆盖机会，避免永远取前两首。采用可注入随机源的加权抽样，便于复现测试。
- 标题提取保留有辨识度的歌曲名称和版本词，仅删除明确装饰或宣传片段；不再无条件删除所有括号内容。有效词不足则跳过，不强行猜测歌手/曲风。
- 合并兴趣查询与通用探索查询，目标配额约 70%/30%，按批次四舍五入，任一池不足由另一池补齐；使用有界轮询填充两类缓冲，不增加每动作请求上限。
- 在“翻唱”等标签中使用“兴趣关键词 + 标签”及“通用标签查询”，让标签也有个性化；标签仍是搜索约束，不保证严格分类。
- 喜欢变化或新增有效收听后标记种子过期；在换批或下次追加时更新查询源。当前可见内容及滚动位置保持，保留仍有效查询的页码，代际标记阻止旧请求覆盖新状态。

### 第三阶段：可解释反馈与排序
- 推荐条目的操作菜单增加“不感兴趣”，支持即时撤销，并提供设置内清除推荐偏好的入口；首版仅屏蔽该 BV，避免扩大到歌手或 UP 主。
- 统计本地实际播放的时间，排除暂停、缓冲、拖动跳跃和加载失败。累计有效收听达到 min(60 秒, 已知时长的 50%) 作为正反馈；时长未知用 60 秒。单曲循环每天最多计一次兴趣增强。
- 用户主动切换且有效播放不足 10 秒记一次弱负反馈；至少两次独立播放会话的早跳才产生降权，7 天衰减。不将自然结束、错误、上一首、拖动、退出或定时停止算作早跳。
- 显式不感兴趣作为硬过滤；其余使用简单规则分数：接口名次归一化至 0–1 乘 3，喜欢线索 +3，有效收听线索 +2，近期已听 -2，7 天曝光 -3，重复早跳 -2，最近 30 条作者过密 -2，高置信标题重复 -2，已知不足 45 秒 -1。同类信号不累加；按配额分别选池后合并，平分保持稳定顺序。
- 首屏前六条优先选择分数高且作者分散的候选；全批仍遵守单 UP 主上限，精选不承诺人工挑选或音乐质量评级。
