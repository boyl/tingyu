# tingyu Windows 实施与验收规范

状态：用户已批准；Windows 开发版实现、工程验收及整包构建完成，真实环境验收边界见文末。日期：2026-10-26。

## 目标与基线

基于 boyl/tingyu main 当前 0.1.28+29，实现可直接运行的 Windows x64 桌面版本。UI 交互与视觉以现有 macOS 桌面工作区、现行 UI 规范及已确认截图为基线；不得重做为另一套 Windows 风格界面。

已确认：项目已有 Windows runner、libmpv 音频依赖、SMTC、托盘与打包脚本。lib/main.dart 的 createRouter 仅在 Platform.isMacOS 时使用 MacWorkspace；Windows 尚未接入这套桌面入口。主题未明确配置共同字体，需核查字体度量和许可证。当前 shell PATH 未发现 Flutter / Dart / CMake，不能据此认定整机未安装。

## 方案与兼容

沿用现有 Flutter MVC 职责划分：共享模型、Riverpod 控制器、桌面视图；Windows 音频、系统媒体、凭据、托盘、窗口由现有边界服务实现。避免复制 Mac UI 形成第二套代码。Android 路由及交互保持回归覆盖，macOS 既有行为不得退化。

一致性范围包含导航、页面、弹层、播放栏、歌词、主题、图标、间距、字号、动画、悬停/按下/焦点、键盘及滚动反馈。原生标题栏、文件选择器、系统媒体面板及系统字体的跨系统差异须逐项调查；未经确认不得将其自动排除于用户要求。若 Apple 字体不能合法分发，记录阻塞及候选共同字体，不能直接宣称完全相同。组件截图不能代替原生窗口与真实音频证据。

## 分阶段任务

1. 核对本地既有源码入口、所有权与远端；没有现成入口时在当前交互用户下克隆至 Documents/repo/tingyu。固定实施 SHA，读取全部相关项目规则。定位现有工具链并检查 Flutter、Visual Studio C++ 与 Windows SDK；缺失项列明后按授权配置。
2. 建立 Windows 路由缺失的失败回归；共享桌面工作区及必要平台判断。审核键盘修饰键、窗口边框、主题默认值、字体和弹层上下文，修复真实差异，不无关重构。
3. 在 Windows 构建并启动：验证音频初始化、媒体控制、凭据错误恢复、托盘隐藏/恢复、退出落盘、下载与缓存路径；所有错误明确可恢复。
4. 同数据、尺寸、主题、字体比例下生成独立 Windows 对照图，逐页比对 Mac 基线；修复布局及状态差异，保留差异证据，不覆盖历史基线。
5. 执行项目工程验收及原生场景。生成完整 Release 便携 ZIP（EXE、DLL、data）、SHA-256、简体中文运行说明与验收结果。未授权不提交、推送或发布。

## 核心体验与状态

核心任务：打开应用→搜索/导入音乐→播放→整理歌单/下载→重启恢复。入口、完成反馈与退出方式沿用 Mac。

| 状态 | 可见反馈与允许操作 | 恢复与保留 |
|---|---|---|
| 首次/空库 | 桌面歌曲页，搜索与导入入口 | 不呈现移动端导航 |
| 加载/下载/登录等待 | 原有进度或等待状态，允许已有取消操作 | 不改变核心区域几何 |
| 播放/暂停/完成 | 播放栏、歌词、队列和系统媒体状态一致 | 切页不重建播放器 |
| 无曲目/禁用 | 控件正确禁用，语义可识别 | 不能产生无效播放请求 |
| 网络/凭据/存储失败 | 原有错误与重试入口 | 不删凭据，不明文降级 |
| 隐藏/退出/重启 | 托盘可恢复，显式退出完成清理 | 保存偏好、队列和进度，恢复暂停 |
