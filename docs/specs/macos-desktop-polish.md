按 design-review/2026-10-24/macos-audit/REVIEW.md 收敛桌面视觉。移除没有独立任务的主页；默认最近播放，无历史时进入歌曲。保留歌词在详情、队列浮出不压缩主内容、侧栏歌单与创建入口、播放模式及核心动作。兼容旧 library 初始页参数；Android/Windows 路由和默认控件反馈不变。不更改播放、登录、持久化契约，不覆盖现有播放偏好修复。

## 启动钥匙串故障修复（2026-10-24）

原生窗口实际显示 PlatformException 启动失败；系统日志为钥匙串访问取消，进程采样确认 `SecItemCopyMatching` 等待授权，用户截图确认“登录”钥匙串密码框。本地 ad-hoc 重签后的旧凭据访问是触发条件。

- 凭据读取原生异常转为明确账号错误；控制器仅隔离此账号恢复失败，继续读取本地资料库，不删除凭据，不影响数据库/播放器失败的原有处理。
- 预览版启动读取使用插件提供的非交互选项；传统登录钥匙串仍可能等待系统授权，因此增加五秒读取上限。迟到结果不建立会话；写入和删除仍使用正常系统授权，不做明文降级。
- 回归先确认取消授权导致初始化失败，再验证本地歌曲仍可恢复、未登录状态、凭据未删除，以及未响应授权五秒后明确失败。凭据专项 5 项通过；最终全量与原生重启记录待本轮完成后补充。
- 最终修复版原生重启后，CUA 实际窗口已从启动页进入“歌曲”，语义树与截图均显示原有 80 首歌曲，未注入夹具；确认本地资料库可恢复。真实账号重新授权、扫码与有声播放未在本轮执行，不扩大此启动验收结论。
- 最终 `python3 tool/run_acceptance.py` 全部 PASS（含源码稳定性），指纹 `81b308cb1aa3006acd58be246c5b6eba4714cd801b586e47a992aded4a063b9a`；专项 5 项通过，Mac 重建及严格签名验证通过。此前两次验收期间仍在修改源码，稳定性门禁按实记录 FAIL；最终停改后重跑通过，不以中间结果交付。
